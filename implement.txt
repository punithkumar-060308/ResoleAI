RESOLVEAI — IMPLEMENTATION MASTER PLAN
Build Bengaluru Hackathon — Customer Support Track

1. PROJECT GOAL
ResolveAI is an autonomous customer-support intelligence platform. It does not simply answer questions. It investigates a customer's complete situation across enterprise data, identifies root cause, determines the best resolution, safely executes low-risk actions, and escalates complex/risky cases with full context.

CORE FLOW:
Customer -> Understand -> Investigate -> Gather Evidence -> Qwen Reasoning -> Root Cause -> Risk Check -> Decide -> Act/Escalate -> Respond -> Audit

2. PROBLEM
Large companies receive thousands of support requests across chat, email, tickets and other channels. Existing systems often treat tickets independently, forcing agents to manually search CRM, orders, billing, shipment, previous conversations and policies. This creates slow responses, repetitive questions, inconsistent resolutions, unnecessary escalation and higher support costs.

KEY GAP:
A chatbot answers an FAQ. ResolveAI investigates the customer's actual situation using multiple data sources before deciding what should happen.

3. PROPOSED SOLUTION
When a customer submits a complaint, ResolveAI:
1) understands intent, urgency and sentiment
2) identifies the customer and ticket
3) retrieves customer history
4) checks orders and shipment
5) checks payments/refunds
6) checks previous support interactions
7) retrieves relevant policies
8) builds a structured evidence package
9) uses Qwen for reasoning/root-cause analysis
10) determines resolution
11) performs safe low-risk actions
12) requests human approval for high-impact cases
13) escalates complex cases with complete context
14) generates a personalized response
15) records an audit trail
16) updates analytics

4. KILLER DEMO
Customer: "My order hasn't arrived and I was charged twice. I already contacted support yesterday."

System finds:

- Generate response

IMPORTANT: The agents are logical roles, not necessarily seven separate AI models. Use Qwen where reasoning is needed; ordinary API/database tools can handle retrieval.

6. AGENTS
1. Orchestrator: decides what needs investigation and coordinates workflow.
2. Customer Intelligence: profile, tier, previous tickets, complaints, history, sentiment/context.
3. Order Investigation: order, shipment, delivery, delay, cancellation, return, SLA.
4. Billing: payments, duplicate charges, failed payments, refunds.
5. Knowledge/Policy: refund, compensation, escalation and eligibility rules.
6. Resolution: combines evidence and recommends resolve/refund/replace/compensate/escalate/human review.
7. Response: generates personalized customer response.

7. QWEN
Use Qwen for:
- intent classification
- urgency
- sentiment
- issue identification
- evidence interpretation
- root-cause analysis
- resolution recommendation
- escalation decision
- structured output
- response generation
- tool/function calling if available

Preferred JSON:
{
  "intent": "...",
  "urgency": "...",
  "sentiment": "...",
  "issues": [],
  "root_causes": [],
  "evidence": [],
  "recommended_actions": [],
  "risk_level": "...",
  "needs_human": true,
  "reason": "..."
}

Do not expose hidden chain-of-thought. Display concise evidence and conclusions.

8. MULTI-SOURCE INVESTIGATION ENGINE
Input: ticket_id

Retrieve:
- customer profile
- relevant orders
- shipment
- payment history
- refunds
- previous support tickets
- relevant policies

Then:
data -> evidence package -> Qwen -> investigation result

Add contradiction detection. Example: previous support says refund processed, refund system says pending. Flag the conflict, increase risk and require human review.

9. RISK-BASED AUTOMATION
LOW RISK:
ticket updates, tracking/status messages, internal notes -> can be automated.

MEDIUM RISK:
small compensation, replacement, refund -> validate against policy and/or require approval.

HIGH RISK:
fraud, large refund, account takeover, identity uncertainty, conflicting data -> human approval.

SAFE PATTERN:
Qwen recommends -> backend validates -> policy/risk check -> EnterPro executes -> action logged.

10. HUMAN-IN-THE-LOOP
Approval screen must show:
customer, complaint, history, order, payment, previous tickets, policies, evidence, root cause, AI recommendation, risk, actions already taken, Approve/Reject/Escalate.

Goal: AI investigates; humans make informed decisions when required.

20. COPY-PASTE VIBE-CODING PROMPTS

PROMPT 1 — FRONTEND
"Build a production-quality React + Vite + Tailwind CSS frontend for ResolveAI, an autonomous customer support intelligence platform. Create customer chat, support dashboard, ticket details, customer profile, investigation timeline, evidence panel, AI recommendation panel, human approval screen and analytics dashboard. Start with realistic mock data. Use reusable responsive components and enterprise UI. Do not implement backend yet."

PROMPT 2 — BACKEND
"Build a modular Node.js + Express backend for ResolveAI using PostgreSQL. Create schema/models, seed data and REST APIs for customers, tickets, orders, payments, support history, policies, investigations, recommendations, escalations and audit logs. Add validation, error handling and clear service/repository separation."

PROMPT 3 — QWEN
"Integrate Qwen into ResolveAI as the AI reasoning engine. Given a customer support request and structured evidence, return validated JSON containing intent, urgency, sentiment, issues, evidence findings, root causes, recommended actions, risk level and human-escalation requirement. Add robust parsing, validation, timeout/error handling and fallback behavior. Do not expose hidden chain-of-thought."

PROMPT 4 — INVESTIGATION
"Build a multi-source investigation service for ResolveAI. Given a ticket ID, retrieve the customer profile, relevant orders, payment history, previous support tickets, shipment information and relevant company policies. Combine them into a structured evidence package. Detect contradictions and flag high-risk cases. Return concise evidence and findings for the Qwen reasoning layer."

PROMPT 5 — ENTERPRO
"Implement the ResolveAI enterprise workflow using EnterPro. Orchestrate ticket intake, intent analysis, customer investigation, order investigation, billing investigation, policy retrieval, Qwen reasoning, risk validation, action execution, human escalation, response generation and audit logging. Preserve complete context during human handoff."

PROMPT 6 — INTEGRATION
"Connect the ResolveAI React frontend, Express backend, PostgreSQL database, Qwen service and EnterPro workflow into one end-to-end application. Implement loading states, errors, approval flow, escalation flow, audit logging and analytics. Create a reliable demo flow using realistic seeded enterprise data."

25. RELIABILITY RULES
- Never allow unrestricted LLM database writes.
- Validate AI recommendations in backend/business rules.
- Use risk levels.
- Require human approval for high-impact actions.
- Detect conflicting enterprise data.
- Log every action.
- Preserve complete context during escalation.
- Use simulated data when real enterprise integrations are unavailable.
- Never expose hidden chain-of-thought.

26. FINAL PRINCIPLE
ResolveAI must not look like:
"LLM + chat UI."

"Enterprise Data + Investigation + Reasoning + Workflow + Controlled Action + Human Oversight."
